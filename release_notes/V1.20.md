# Personal Task-Based Work Log V1.20

发布日期：2026-05-31

## 版本定位

V1.20 是进入 AI 任务分析能力之前的一次稳定发布。

本版本继续保持当前项目的轻量技术栈：

- Python + Flask
- SQLite
- 单页 HTML
- 原生 JavaScript
- 简单 CSS

这次没有引入复杂框架，也没有改变 Task / Log 的主记录链路。重点是为后续 AI 分析功能建立一个可回退、可试用的阶段基线。

## 主要更新

### 1. AI 设置

- 新增 AI API 设置区域。
- 支持 OpenAI-compatible API。
- 支持自定义 Base URL。
- 支持自定义模型名称。
- 支持保存 API Key 到本机配置文件。
- 支持 API 连接测试。
- API Key 不存入日志数据库，避免污染核心工作日志数据。

默认方向兼容硅基流动等 OpenAI-compatible 服务。

### 2. 当前任务 AI 分析

- 当前任务标题区域新增任务分析入口。
- 可基于当前任务日志生成任务复盘。
- 分析结果使用 Markdown 风格展示。
- 分析结果保存到 `analysis_runs` 表。
- 任务分析与日志主链路分离，后续可扩展为周报、月报、分析中心。

当前任务分析重点输出：

- 当前进展
- 已完成内容
- 可能遗漏
- 风险提醒
- 下一步建议

### 3. 后台分析任务

- 任务分析从同步等待改为后台执行。
- 点击分析后，用户可以关闭弹窗，继续写日志或切换任务。
- 分析中按钮会保持显示，作为后台任务提醒。
- 分析完成后按钮显示“查看分析”。
- 分析失败后按钮显示“重新分析”。
- 同一个任务正在分析时，不会重复启动第二个分析任务。

### 4. AI 输出截断处理

- 后端会读取 AI 返回的 `finish_reason`。
- 如果发现输出因为长度限制被截断，会自动请求继续生成。
- 自动合并续写内容。
- 如果续写后仍然被截断，会在结果末尾提示用户。

### 5. 分析按钮状态优化

- 普通“分析”按钮默认隐藏，靠近当前任务标题区域时显示。
- “分析中”“查看分析”“重新分析”保持常显，作为状态提醒。
- 如果分析完成后继续新增日志，按钮回到普通“分析”状态。
- 如果分析过程中新增日志，按钮仍保持“分析中”，不会提前变回“分析”。
- 分析是否过期优先基于 `completed_at` 判断，避免后台分析期间新增日志导致刚完成的结果立刻不可查看。

### 6. 任务导出

- 编辑任务窗口中新增任务导出入口。
- 支持将单个任务导出为 Markdown 文件。
- 导出内容包括任务信息、置顶日志和完整日志记录。
- 该能力为后续 AI 分析、备份、外部复盘保留了基础出口。

### 7. 数据库升级到 schema v5

本版本将数据库升级到 schema v5。

新增 AI 分析记录表：

```text
analysis_runs
```

主要字段：

```text
id
scope_type
task_id
title
result_markdown
status
error_message
model
base_url
start_time
end_time
completed_at
created_at
```

状态字段：

```text
pending
running
completed
failed
```

兼容说明：

- 不修改历史日志内容。
- 不修改 Task / Project 主链路。
- AI 设置保存在本机 `data/ai_settings.json`。
- 未完成的后台分析在应用重启后会标记为失败，可重新分析。

本次升级前已备份真实数据库到：

```text
backup/
```

### 8. 细节修复

- 修复 API 测试接口在部分服务返回空 content 时误判失败的问题。
- 修复分析完成后新增日志时按钮状态不符合预期的问题。
- 修复分析中新增日志后，按钮提前变成“分析”的问题。
- 修复分析按钮隐藏策略过强，导致结果提醒不明显的问题。

- `dist/`
- `releases/`

## 便携版说明

便携版入口：

```text
dist/PersonalWorkLog/Worklog.exe
```

便携版运行数据目录：

```text
dist/PersonalWorkLog/data/worklog_v3.db
```

复制整个 `PersonalWorkLog` 文件夹到其他 Windows 电脑后，可以直接运行 `Worklog.exe` 试用。
