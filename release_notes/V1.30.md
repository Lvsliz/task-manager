# Personal Task-Based Work Log V1.30

发布日期：2026-05-31

## 版本定位

V1.30 是进入 AI 阶段分析和任务迁移能力后的稳定试用版本。
本版本继续保持 Flask + SQLite + 单页原生 JavaScript 的轻量结构，重点增强 AI 分析中心、提示词预设、分析历史标记，以及任务导入导出链路。

## 主要更新

### 1. 任务分析中心增强

- 左侧“任务分析”入口继续作为分析中心入口。
- 分析中心中将“阶段总结”前置为第一模块。
- 支持生成本周总结、半月总结、本月总结、半年总结、年度总结和自定义阶段总结。
- 阶段总结只分析所选时间范围内实际发生过日志更新的任务。
- 长期任务如果在所选时间范围内有日志，会被纳入本阶段分析，但只分析本阶段内的推进情况。

### 2. 快速分析与阶段分析区分

- 当前任务右上角的分析入口统一命名为“快速分析”。
- 分析历史中明确显示来源标签：
  - 快速分析
  - 周报
  - 半月总结
  - 月报
  - 半年总结
  - 年度总结
  - 自定义总结
- 历史记录标题拆分为“标签 + 标题内容”，为后续按标签筛选分析历史做准备。

### 3. 提示词预设

- 提示词设置支持不同分析类型分别设置。
- 支持多种提示词风格预设：
  - 务实复盘
  - 简约总结
  - 管理汇报
  - 风险排查
  - 行动计划
  - 4F 复盘
- 新增“简约总结”风格，用于生成简短、可直接填写汇报的内容。
- 保存提示词时会保留对应的预设风格，不再错误地一律变成自定义。

### 4. 分析记录数据增强

数据库升级到 schema v6。

`analysis_runs` 新增字段：

```text
prompt_preset
prompt_preset_label
prompt_snapshot
```

这些字段用于记录分析生成时使用的提示词风格和提示词快照，避免后续修改提示词后影响历史分析记录的可追溯性。

### 5. 任务导出

- 任务编辑弹窗中支持导出单个任务为 Markdown。
- 导出内容包含任务基本信息、置顶日志和完整日志记录。
- 导出文件用于人工阅读、外部复盘和后续任务导入。

### 6. 任务导入

- “新建任务”弹窗中新增“导入任务文件”入口。
- 支持导入本工具导出的 Markdown 任务文件。
- 导入会创建新任务，不覆盖已有任务。
- 如果目标项目不存在，会自动创建项目。
- 如果同一项目下已有同名任务，会自动生成“任务名（导入）”形式的新名称。
- 支持导入日志记录，并尽量恢复置顶日志。

### 7. 其他细节

- 修正提示词标题中不适合报告书写的斜杠表达。
- 优化分析历史列表的视觉层级。
- 保持现有日志输入、任务列表、项目切换和提醒逻辑不变。

## 数据与隐私说明

本次发布包不包含任何本机已有数据。

发布包排除内容包括：

```text
worklog_v3.db
backup/
data/ai_settings.json
server.out.log
server.err.log
build/
dist/
releases/
__pycache__/
```

便携版只包含空的 `data/` 目录。首次运行时会自动创建新的本地数据库和设置文件。
